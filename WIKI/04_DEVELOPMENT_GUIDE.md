# 04. Руководство разработчика: запуск, тестирование и расширение

## 1. Быстрый запуск сервиса в 1 команду

Вся система спроектирована так, чтобы запускаться мгновенно без сложных зависимостей:
ash
python backend/run.py  # или python -m uvicorn backend.app.main:app --port 8080 --reload
```

После запуска в терминале:
* **Веб-интерфейс (UI)**: откройте в браузере **[http://localhost:8080](http://localhost:8080)**
* **Интерактивная документация Swagger**: откройте **[http://localhost:8080/docs](http://localhost:8080/docs)**
* **Проверка здоровья (Health Check)**: **[http://localhost:8080/api/health](http://localhost:8080/api/health)**

## 2. Сквозной пользовательский сценарий (User Flow)

1. **Создание / Выбор проекта**:
   * В верхней панели выберите проект или нажмите `+ Новый проект`.
2. **Этап 1: Первичная смета ⟶ Структура**:
   * Загрузите файл сметы (например, `Примеры смет/GIGASCHOOL - смета на разработку мобильного приложения - .xlsx`).
   * Нажмите кнопку **«⚡ Сгенерировать структуру»**.
   * Сервис распарсит смету и построит интерактивное дерево экранов и элементов прямо в веб-интерфейсе (вкладка `🗺️ Интерактивный холст`).
   * Нажмите **«Утвердить структуру ⟶ Перейти к созвонам»**.
3. **Автоматическая отрисовка архитектуры в FigJam (без Ctrl+V, 100% программно)**:
   * В приложении **Figma Desktop** откройте или создайте доску FigJam (`New FigJam board`).
   * Откройте меню: **Plugins ⟶ Development ⟶ Xpage ППО FigJam Sync** (или правой кнопкой на холсте ⟶ `Plugins` ⟶ `Development` ⟶ `Xpage ППО FigJam Sync`).
   * В окне плагина статус покажет: `🟢 Сервис ППО подключен (localhost:8080)`.
   * Выберите проект (например, `Сквозной кейс: Приложение ломбарда (Xpage)`).
   * Нажмите кнопку **«⚡ Нарисовать на холсте FigJam»**.
   * Плагин мгновенно построит корпоративную визуальную архитектуру экранов Xpage: вертикальные стеки карточек экранов (фиолетовые шапки `#7C3AED`, белые карточки функциональных блоков с рамками, левым выравниванием текста), навигационные вкладки (`PILL`) и ортогональные векторные стрелки `#3B82F6` с привязкой к магнитам.
4. **Этап 2: База знаний созвонов ⟶ Анализ противоречий**:
   * Загрузите файл встречи (например, `Транскрибация созвонов с клиентом/19.06.2026_обезличено_обсуждение_технических_требований.docx` или аудиофайл).
   * Нажмите **«🔍 Запустить кросс-анализ»**.
   * Сервис рассчитает **индекс готовности требований (DoR)**, выведет реестр подтвержденных требований (`REQ-01`...) и карточки противоречий с готовыми вопросами клиенту.
5. **Этап 3: Синхронизация с FigJam / Figma**:
   * Вставьте ссылку на доску FigJam или ключ файла Figma.
   * Нажмите **«🔗 Прочитать элементы через Figma REST API»** для обогащения ТЗ компонентами интерфейса.
6. **Этап 4: Генерация официального Технического задания (DOCX)**:
   * Нажмите **«📄 Сгенерировать ТЗ (.docx)»**.
   * Движок `tz_generator.py` скомпилирует документ Microsoft Word строго по шаблону `Шаблон Технического задания (ТЗ) Xpage.md` (380+ параграфов, 18 таблиц, 11 корпоративных разделов, лист согласования, матрица RBAC/CRUD, спецификация API, реестр требований REQ-01 и NFR).
   * Нажмите **«⬇ Скачать готовое ТЗ (.docx)»** для скачивания документа на компьютер.

## 3. Архитектура эндпоинтов REST API

| Метод | URL | Описание |
| :--- | :--- | :--- |
| GET | /api/health | Проверка статуса сервера и конфигурации API-ключей |
| GET | /api/projects | Список всех проектов ППО |
| POST | /api/projects | Создание нового проекта |
| POST | /api/structure/upload-estimate/{id} | Загрузка и парсинг Excel-сметы |
| POST | /api/structure/generate/{id} | AI-генерация структуры модулей и экранов |
| PUT | /api/structure/update/{id} | Ручное редактирование утвержденной структуры |
| POST | /api/analysis/upload-transcript/{id} | Загрузка созвона (DOCX или аудио MP3/WAV) |
| POST | /api/analysis/run-analysis/{id} | Запуск поиска противоречий, пробелов и вопросов |
| POST | /api/figjam/sync/{id} | Синхронизация с доской FigJam через Figma REST API |
| POST | /api/tz/generate/{id} | Генерация файла ТЗ по стандарту Xpage |
| GET | /api/tz/download/{id} | Скачивание сгенерированного файла .docx |
