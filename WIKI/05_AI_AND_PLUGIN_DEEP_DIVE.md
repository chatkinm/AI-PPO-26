# 05. Глубокое погружение: AI-модели, корпоративные шаблоны, ограничения и архитектура FigJam плагина

В этом документе детально зафиксированы принципы работы нейросетевого контура, происхождение шаблонов, методы обхода ограничений LLM и внутреннее устройство плагина FigJam.

## 1. Нейросетевой контур: как работают модели и за счет чего

Сервис предпроектного обследования (ППО) не полагается на одну модель, а использует **двухконтурную специализированную архитектуру**:

1. **Контур распознавания речи (Audio Pipeline)**:
   * Модель: **Whisper Large V3** (через Groq Cloud API).
   * Вход: Аудиозапись созвона (MP3, WAV, M4A, OGG).
   * Выход: Полная расшифровка на русском языке с тайм-кодами и разделением фраз.
   * За счет чего работает: специализированная акустическая модель глубокого обучения (OpenAI Whisper), запущенная на тензорных чипах LPU (Language Processing Units). Скорость обработки достигает 300 слов в секунду (часовая встреча расшифровывается за 15-20 секунд).

2. **Контур логики и системного анализа (LLM Pipeline)**:
   * Модели: **Каскад моделей** (openai/gpt-oss-120b, openai/gpt-oss-20b, qwen/qwen3.8-27b, а также Google Gemini Flash в качестве альтернативы).
   * Вход: Распарсенные строки сметы (openpyxl) и транскрипции созвонов.
   * Выход: Строго валидированные структуры данных Pydantic (ProjectStructure и AnalysisReport).
   * За счет чего работает: семантический анализ текста с низкой температурой (	emperature=0.2) и режимом принудительного структурированного вывода (
esponse_format=json_object).

## 2. Корпоративные шаблоны: какие используются и откуда они

В сервисе задействованы два фундаментальных корпоративных шаблона:

1. **Шаблон Технического задания (ТЗ) Xpage (Шаблон Технического задания (ТЗ) Xpage.md)**:
   * **Откуда взят**: Основан на реальных утвержденных технических заданиях агентской разработки IT-компании Xpage (в частности, боевом документе Примеры ТЗ/ТЗ на ломбард.docx, содержащем 196 подразделов и 2376 параграфов).
   * **Состав (11 обязательных разделов)**:
     - Титульный лист и лист согласования (PM, CTO, PO, IT-директор) с версионностью Changelog;
     - Раздел 1: Глоссарий (11+ терминов: API, BFF, CMS, NavBar, WebView, Push SDK, DeepLink и др.);
     - Раздел 2: Назначение, измеримые KPI и границы проекта (Scope In/Out) + **Раздел 2.5 с DoR-индексом и реестром требований REQ-01 из созвонов**;
     - Раздел 3: Пользовательские роли и матрица прав доступа (RBAC/CRUD);
     - Раздел 4: Системная архитектура (Frontend -> BFF Gateway -> 1C -> SMS/Эквайринг);
     - Раздел 5: Структура экранов со ссылкой на интерактивный прототип FigJam;
     - Раздел 6: Функциональные требования к экранам (UI-элементы, валидации, источники данных);
     - Раздел 7: Сквозные Use Cases (бизнес-сценарии с альтернативными потоками);
     - Раздел 8: Нефункциональные требования (NFR, SLA <250мс, <1.5с 1С, Uptime 99.7%, ФЗ-152, AES-256);
     - Раздел 9: Административная панель (CMS);
     - Раздел 10: Требования к тестированию и критерии приемки;
     - Раздел 11: План-график реализации и 60 дней гарантийных обязательств.

2. **Матрица полноты требований (Чек-лист полноты информации по проекту с рисками (для этапа ППО).md)**:
   * **Откуда взят**: Внутренний корпоративный стандарт аудита проектов Xpage.
   * **Назначение**: Проверка созвонов на предмет «белых пятен» (необсужденных критических сценариев: сбои платежей, чеки 54-ФЗ, пустые состояния экранов).

## 3. Ограничения нейросетей и методы их обхода (Guardrails)

1. **Галлюцинации (придумывание фактов)**:
   * *Опасность*: Нейросеть может выдумать технический протокол или финансовые условия, которых клиент не озвучивал.
   * *Как обходим*: Жесткий системный промпт с правилом: СТРОГИЙ ЗАПРЕТ: Не выдумывай факты. Опирайся только на цитаты из созвонов!. Если в материалах нет ответа, модель обязана не додумывать, а создать уточняющий вопрос клиенту (clarifying_question) в блоке inconsistencies. Все действия контролирует человек (Human-in-the-Loop).

2. **Нестабильность формата вывода**:
   * *Опасность*: Модель может вернуть текст с вступительными фразами вместо машинного JSON, сломав веб-интерфейс.
   * *Как обходим*: Pydantic Structured Outputs. В API передается сгенерированная JSON-схема (schema.model_json_schema()), включается 
esponse_format={'type': 'json_object'}, а в i_service.py реализована очистка от markdown и fallback-парсинг.

3. **Лимит контекстного окна**:
   * *Опасность*: Большие транскрипции нескольких встреч перегружают контекст малых моделей.
   * *Как обходим*: Токенизационная предобработка. Сметы предварительно парсятся через openpyxl, убирая пустые ячейки и формулы Excel (экономия 80% токенов).

4. **Падение провайдера и Rate Limits (429)**:
   * *Опасность*: Превышение квот токенов блокирует работу.
   * *Как обходим*: Каскадный Fallback (models_to_try). При сбое модели gpt-oss-120b сервис автоматически переключается на gpt-oss-20b и qwen3.8-27b.

5. **Искажение корпоративного оформления ТЗ**:
   * *Опасность*: Если поручить LLM писать 50 страниц Word целиком, она сократит текст и потеряет форматирование.
   * *Как обходим*: Детерминированный движок 	z_generator.py. Документ компилируется программным скриптом на базе эталонного Markdown-шаблона Xpage. Нейросеть генерирует только подтвержденные факты, а движок вставляет их в таблицы с правильными цветами (#1E293B), защитой cantSplit и колонтитулами.

## 4. Архитектура и устройство плагина FigJam (igjam-plugin/)

### 4.1. Почему именно плагин, а не Figma REST API?
* В официальном Figma REST API методы создания объектов на холсте **отсутствуют в принципе (Read-Only)**. Через REST API можно только читать существующие файлы.
* Единственный официальный способ программно рисовать фигуры и связи на холсте без ручного Ctrl+V — это **Figma Plugin API**.

### 4.2. Откуда плагин берет информацию?
Плагин обращается к локальному серверу ППО по HTTP:
1. GET /api/figjam/projects — список проектов со структурой.
2. GET /api/figjam/nodes/{project_id} — массив предрассчитанных координат (x, y), размеров карточек, цветов заливок, шрифтов и магнитов коннекторов, сформированный модулем igjam_layout.py.

### 4.3. За счет чего плагин работает (двухконтурная архитектура)?
1. **Контур UI (ui.html)**: работает в Chromium iframe, имеет сетевой доступ (etch) и скачивает координаты с localhost:8080.
2. **Контур холста (code.js)**: работает в изолированной C++ песочнице QuickJS, имеет доступ к глобальному объекту igma, создает элементы (createShapeWithText, createConnector) и управляет камерой (iewport.scrollAndZoomIntoView).
3. **Мост PostMessage**: ui.html передает загруженный JSON в code.js через parent.postMessage({ pluginMessage: { type: 'DRAW_STRUCTURE', payload } }, '*'). За доли секунды на холсте строится корпоративная схема Xpage.
